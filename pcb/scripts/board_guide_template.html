1. Overview

This board breaks out every I/O pin of the dsPIC33CK256MC005-I/PT (48-pin TQFP, 7 × 7 mm, 0.5 mm pitch) to two 22-pin 2.54 mm headers. Its form factor follows Microchip's Curiosity Nano boards: a narrow stick that plugs straight into a solderless breadboard. It contains only what the MCU needs to run (power, decoupling, reset and programming), plus a UART header, two LEDs and two buttons.

Key features

  • dsPIC33CK256MC005: 100 MIPS, 256 KB flash, 24 KB RAM, motor-control PWM, 3 op-amps, 12-bit ADC
  • USB-C power input (power only, no USB data)
  • MCP1703A-3302 LDO: 3.3 V, 250 mA
  • Ferrite-filtered analog supply (AVDD)
  • 6-pin ICSP header for PICkit 4/5, MPLAB Snap or ICD
  • 4-pin UART header (3V3 / TX / RX / GND)
  • RESET and USER buttons, power and user LEDs
  • All 0805 resistors and capacitors, easy to hand-solder

4. Power supply

USB-C input

J1 is a 6-pin power-only USB-C receptacle (GCT USB4125). R1/R2 (5.1 kΩ) pull CC1 and CC2 to ground, which tells the host or charger that this is a "sink" device. Without them, a USB-C charger supplies no power. The board asks for default USB power (500 mA from a USB 2.0 port, up to 1.5–3 A from a charger). It only needs a fraction of that.

Reverse-feed protection

D1 (B5819W Schottky) sits between VBUS and the board's 5 V rail. The 5V header pin is on the protected side, so 5 V applied to that pin cannot flow back into a connected PC. The diode drops about 0.3–0.4 V, so the 5 V rail is about 4.6 V. That leaves plenty of headroom for the 3.3 V LDO.

3.3 V regulator

Analog supply

The MCU's AVDD (pin 13) powers the ADC, op-amps, comparators and DAC. It is fed through FB1, a 600 Ω at 100 MHz ferrite bead, and decoupled with C7 100 nF + C8 1 µF, which keeps digital switching noise out of analog measurements. AVSS (pin 14) goes straight to the ground plane.

Powering from the headers: you can power the board from 5 V on J2-1 (5V), or from 3.3 V on J3-1 (3V3), which bypasses the LDO. Never feed 3.3 V into the 3V3 pin while USB-C is also connected. The UART header's 3V3 pin is the same rail, so connect it only if the USB-serial adapter is meant to power the board.

7. Programming and debugging (J4, ICSP)

J4 is a 6-pin 2.54 mm header in Microchip's standard ICSP order. Pin 1 is marked with a square pad and the MCLR label.

PinSignalConnects to
1MCLR / VPPU1 pin 5
2VDD (3.3 V)+3V3 rail (the programmer senses the target voltage)
3GNDGround
4PGDPGD3 / RB5, U1 pin 33
5PGCPGC3 / RB6, U1 pin 34
6—Not connected (LVP/aux on PICkit)

PGD3/PGC3 were chosen because the other two programming pairs share pins with useful peripherals: PGx1 = RB8/RB9 carries I²C1, and PGx2 = RB3/RB4 carries op-amp 2's inputs. Your firmware must select PGx3 in its configuration bits (see the firmware section). Otherwise debugging won't connect.

Power the board from USB-C while programming. A PICkit can also power the target from pin 2, but don't do both at once.

10. Firmware starter (MPLAB X + XC-DSC/XC16)

A minimal program for this board: 100 MIPS from the internal oscillator, UART1 on J5 at 115200 baud, and the user LED following the button.

#include <xc.h>

// ---- configuration bits ----
#pragma config FNOSC = FRC          // start on FRC, switch to PLL in code
#pragma config FCKSM = CSECMD       // clock switching enabled
#pragma config ICS   = PGD3         // debugger on PGC3/PGD3 (J4) -- required!
#pragma config JTAGEN = OFF
#pragma config FWDTEN = ON_SW       // watchdog under software control

#define FCY 100000000UL             // 100 MIPS

static void clock_init(void)
{
    // FRC 8 MHz: FPLLO = 8 MHz * M / (N1 * N2 * N3) = 8 * 150 / (1 * 3 * 1) = 400 MHz; FCY = FPLLO/4 = 100 MHz
    CLKDIVbits.PLLPRE = 1;
    PLLFBDbits.PLLFBDIV = 150;
    PLLDIVbits.POST1DIV = 3;
    PLLDIVbits.POST2DIV = 1;
    __builtin_write_OSCCONH(0x01);  // new oscillator: FRC + PLL
    __builtin_write_OSCCONL(OSCCON | 0x01);
    while (OSCCONbits.OSWEN);       // wait for switch
    while (!OSCCONbits.LOCK);       // wait for PLL lock
}

static void pins_init(void)
{
    __builtin_write_RPCON(0x0000);  // unlock PPS
    _RP58R = 1;                     // RC10/RP58 -> U1TX   (J5 pin 2)
    _U1RXR = 59;                    // U1RX <- RC11/RP59    (J5 pin 3)
    __builtin_write_RPCON(0x0800);  // lock PPS

    _TRISC10 = 0;  _TRISC11 = 1;  _CNPUC11 = 1;   // UART: TX out, RX in with pull-up
    _TRISC13 = 0;  _LATC13 = 1;                   // user LED off (active low)
    _TRISC12 = 1;                                 // user button input (external pull-up)
}

static void uart1_init(unsigned long baud)
{
    U1MODEbits.BRGH = 0;                          // standard (16x) baud mode
    U1BRG = (FCY / (16UL * baud)) - 1;            // assumes UART clock = FCY (default); see note below
    U1MODEbits.UTXEN = 1;
    U1MODEbits.URXEN = 1;
    U1MODEbits.UARTEN = 1;
}

static void uart1_putc(char c) { while (U1STAHbits.UTXBF); U1TXREG = c; }
static void uart1_puts(const char *s) { while (*s) uart1_putc(*s++); }

int main(void)
{
    clock_init();
    pins_init();
    uart1_init(115200);
    uart1_puts("dsPIC33CK Nano ready\r\n");

    while (1) {
        _LATC13 = _RC12;            // LED on while USER button pressed (both active low)
    }
}
Check these against the dsPIC33CK256MC506 family datasheet before relying on them. The register and bit names (_RP58R, _U1RXR, _TRISC10, _CNPUC11, RPINR18/RPOR13) were confirmed in the device header p33CK256MC005.h from the installed device pack. The rest are written from memory and need checking:
  • the PPS output code (U1TX = 1)
  • the __builtin_write_RPCON unlock/lock values
  • whether RC10/RC11 need ANSEL turned off
  • the PLL divider values
  • the UART baud formula, which depends on the UART clock source (U1MODEH.BCLKSEL)
Alternatively, use MCC (MPLAB Code Configurator), which generates verified setup code for the clock, PPS and UART.

Grounding approach

  • Every GND pad has its own short trace and via to the bottom plane. That includes all four MCU ground pins (14, 19, 31, 42), whose vias sit under the chip body.
  • The router was set to make bottom-layer traces 8× more costly than top-layer ones, so the plane stays almost unbroken under the MCU.
  • Stitching vias tie the top-side GND pour to the bottom plane across the whole board, and pour fragments that don't reach a GND pad are removed.
  • A connectivity check confirmed that all 135 GND items (pads, tracks, vias and pour pieces) form one single connected net.

13. Assembly notes

  1. Order of soldering: start with U1 (TQFP-48), then U2, the USB-C connector J1, the passives, the LEDs and the buttons. Fit the pin headers last.
  2. TQFP-48: tack two opposite corner pins, check the alignment on all four sides, then drag-solder with plenty of flux and clear bridges with wick. Pin 1 is marked by the triangle on the silkscreen.
  3. LED polarity: the cathode goes to the pad marked on the silkscreen. D2's cathode goes to GND; D3's cathode goes to RC13.
  4. D1 polarity: the cathode band faces the LDO (+5V side).
  5. Pin headers: insert them from the bottom with the long pins pointing down, and solder from the top. To keep them straight, push the headers into a breadboard first, lay the board on top and then solder.
  6. Clean the flux off, especially around the TQFP and MCLR network. Leftover flux can leak current on high-impedance nodes.

14. Bring-up checklist

  1. Before applying power: check for shorts with a meter. 5V to GND, 3V3 to GND and 3V3A to GND should each read high resistance, not 0 Ω.
  2. Plug in USB-C: the green PWR LED should light up. Measure the 3V3 pin: 3.25–3.35 V. Measure the 5V pin: about 4.6 V.
  3. Measure AVDD at C8: it should equal 3V3.
  4. Measure MCLR (J4-1): it should be at 3.3 V, and drop to 0 V while RESET is held.
  5. Connect a PICkit to J4 (pin 1 = MCLR). In MPLAB X, choose Read Device ID; it should identify the dsPIC33CK256MC005.
  6. Program the starter firmware. Open a terminal at 115200 8N1 on the UART adapter and look for "dsPIC33CK Nano ready". Press USER and the yellow LED should light.
